# V1.3.0
- A new **3D** tab shows the graph in three dimensions, next to the map rather than instead of it. It draws two sources, each optional: geometries of the graph that carry heights (`POINT Z`, `POLYGON Z` …), and a **Wavefront OBJ** loaded in the tab itself — by button or by dropping it onto the view, together with its `.mtl` for the colours. Geometries without a Z value stay on the map; the tab says how many there are.
- OBJ objects are linked to nodes by name, the same convention as the Blender and CloudCompare links: an object called like a node's label stands for that node. Case and runs of whitespace don't count, and Blender's duplicate suffix (`SU1001.001`) is ignored. The header reports how many objects found their node; objects that found none are shown in grey under their own layer.
- Both sources end up in one metric frame. Coordinates in degrees (EPSG:4326) are projected to the UTM zone of the data, a projected CRS is used as it is — the EPSG code is the one the map asks for, and changing it in either tab changes it in both. An OBJ has no CRS of its own, so it is placed by an origin (easting, northing, height) and an up axis: Y for Blender exports, Z for CloudCompare and survey data. Where the OBJ header names its origin (`E 605211 … N 5339827`), it is taken from there; in the example data, finds and layers therefore line up without typing anything.
- The tab works like the others: hovering opens the quick-info card, a click opens the node in the Explorer, and a node selected elsewhere is brought into view and highlighted while the rest turns translucent (*Fade the rest*). A selected layer lights up on its own, not together with the layers it touches stratigraphically. A single find is shown with its surroundings rather than filling the screen.
- Layers can be coloured **by category**, as on the map: per node type, a connection property — material, find type, interpretation … — splits that layer into sub-layers with their own colours, each of which can be hidden. *OBJ material* uses the colours of the `.mtl` instead.
- An **object list** (*Objects*, top left of the view) shows every node drawn, by type, and hides and shows each one on its own — independently of the layers, so a scene can be coloured by one grouping and thinned out by another. A name filter hides or shows all matches at once, ◎ keeps only that one object, and the Blender keys work too: **H** hides the selected node, **Shift+H** everything else, **Alt+H** brings everything back.
- The 3D view is also available as a Dashboard pane. All panes share the loaded OBJ; layers and hidden objects are set per pane.
- The web version offers *Load example model* in the 3D tab, which loads the OBJ of the example dataset.
- Known limits: textures in the `.mtl` are skipped, only colours are read; the OBJ is not remembered and has to be loaded again after a reload of the page; objects are linked by label only, without the pattern and digit modes of the plugins.
- The **Search** tab has been removed. Its search compared exactly what the search field of the Explorer compares — IDs, labels and all attribute values — while the Explorer also combines it with the type filter and the advanced filters, pages through every match instead of stopping at 300, and passes its filters on to the Charts. Two searches doing nearly the same thing mostly raised the question which one to use. `/` and `Ctrl+K` now jump to the Explorer's search field; in the Dashboard, to an Explorer pane on screen if there is one. A Dashboard pane saved on the Search tab opens as an Explorer pane.
- The WKT reader can now keep the Z ordinate where it is asked to. The map does not ask and reads exactly what it read before; its *Categorise* list now comes from the same function as the 3D tab's, so both offer the same properties.
- New dependency: `three` (three.js). It makes the application about 0.5 MB larger; the standalone build is still one self-contained HTML file.
